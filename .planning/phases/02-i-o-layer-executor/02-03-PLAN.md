<objective>
Build `executor.py` — the I/O dispatcher that receives inert `Action` data from `decide_cycle` and produces GitHub mutations. The executor implements the RFC §4.9 activation state machine (merge-develop into PR branch → handle 204/201/409 → pre-stamp race check → stamp activation status → flip labels), the Pitfall 8 post-squash readback (`_verify_squash` asserting `commit.parents[0].sha == pre_squash_tip` AND running a tree-diff sanity check via `repos.compare_commits` per ROADMAP SC#3 verbatim), the eject handler (overwrite status to failure + cleanup labels), and the lazy comment-ID discovery for `UpdateComment`. Per-handler idempotency tests cover every second-call scenario from RESEARCH.md UK-3. Addresses IO-03, IO-04, IO-05.

PR head branch names — needed by `_handle_activate` for `repos.merge(base=pr_branch, head="develop")` — arrive via an auxiliary `Mapping[int, str]` (PR number → branch name) produced by `build_snapshot` in Plan 02-02 (Path B per W-3 iteration-3 revision). This decouples the pure decision layer (`state.PRState`, `decision.derive_pr`, `_strategies.raw_pr_strategy`) from the executor's I/O-only concern: `branch` has no algorithmic role in `decide_cycle`. The pure layer and Phase 1's 217 tests remain frozen.

Purpose: Connects Phase 1's pure decision output to real GitHub mutations. Idempotency is a load-bearing property for the 3-min cron processor (a cycle that crashes mid-execution must be safe to retry). Post-squash verification (Pitfall 8) defends against the April-2026 GitHub silent corruption incident; the parents[0] check alone catches mis-rebased parents but a true content-corruption could land a commit whose parents[0] is correct but whose tree differs from a legitimate squash — `repos.compare_commits` closes that gap.

Output: `executor.py` with `dispatch()` function (takes `pr_branches` map as final parameter) and five handler functions; `test_executor.py` with ≥21 tests covering all dispatch rows + idempotency scenarios + post-squash verification (parents[0] AND tree-diff) + pr_branches plumbing. No changes to `state.py`, `decision.py`, `_strategies.py`, or conftest fixtures.

    class MissingBranchForActivateError(RuntimeError):
        """Raised when dispatch(Activate(pr=PR)) is called but pr_branches has no entry for pr.number.

        Path B contract (Plan 02-03 iteration-3 revision): branch names live in an auxiliary

    `dispatch(action: Action, client: GitHubClient, owner: str, repo: str, config: MergeQueueConfig, pr_branches: Mapping[int, str]) -> ActionOutcome`:
    ```
    match action:
        case Activate(pr=pr):
            if pr.number not in pr_branches:
                raise MissingBranchForActivateError(
                    f"pr_branches has no entry for PR #{pr.number}; "
                    f"snapshot.build_snapshot must populate it (Path B contract)."
                )
            return _handle_activate(pr, pr_branches[pr.number], client, owner, repo, config)
        case Squash(pr=pr):
            return _handle_squash(pr, client, owner, repo, config)
        case Eject(pr=pr, reason=reason):
            return _handle_eject(pr, reason, client, owner, repo, config)
        case UpdateComment(pr=pr, new_body=body):
            return _handle_update_comment(pr, body, client, owner, repo)
        case Defer(pr=pr, reason=reason):
            return ActionOutcome(action=action, success=True, error_message=None)
        case _:
            assert_never(action)
    ```
    Note that only the Activate case consults `pr_branches` — all other handlers ignore the map entirely. This is the Path B contract: a missing-branch error is structurally impossible for non-Activate actions.

    `_handle_activate(pr: PRState, branch: str, client, owner, repo, config) -> ActionOutcome`:
    - Calls `client.rest.repos.merge(owner, repo, base=branch, head="develop")`. (Note: `branch` arrives as a positional argument from `dispatch`, which looked it up in `pr_branches[pr.number]`. The PRState itself has no `branch` field.)
    - If 201: `new_sha = response.parsed_data.sha`.
    - If 204: re-reads PR head SHA via `pulls.get(...).parsed_data.head.sha` → `new_sha`.
    - If `RequestFailed` with status 409: return `ActionOutcome(success=False, error_message="merge conflict with develop")`.
    - Pre-stamp race check: re-read `pulls.get(...).parsed_data.head.sha`; if != `new_sha`, return `ActionOutcome(success=False, error_message="pre-stamp race: PR head advanced since develop merge")`.
    - Stamp: `client.rest.repos.create_commit_status(owner, repo, new_sha, state="success", context=config.activation_status_context)`.
    - Label flip: `client.rest.issues.add_labels(owner, repo, pr.number, data=[config.active_label])`. Then `_safe_remove_label(client, owner, repo, pr.number, config.queued_label)`.
    - Return `ActionOutcome(action=action, success=True, error_message=None)`.

    `_safe_remove_label(client, owner, repo, pr_number, label)`:
    - Calls `client.rest.issues.remove_label(owner, repo, pr_number, label)`.
    - Catches `RequestFailed` with status 404 → pass (already absent = no-op per RESEARCH.md UK-3).
    - All other exceptions propagate.

    `_handle_squash(pr: PRState, client, owner, repo, config) -> ActionOutcome`:
    - Records `pre_squash_develop_sha` by reading current develop HEAD via `repos.get_branch(owner, repo, "develop").parsed_data.commit.sha`.
    - Calls `client.rest.pulls.merge(owner, repo, pr.number, merge_method="squash")`.
    - If `RequestFailed` with status 405: return `ActionOutcome(success=True, error_message="already merged — no-op")`.
    - On success: `squash_sha = response.parsed_data.sha`.
    - Calls `_verify_squash(client, owner, repo, pr, pre_squash_develop_sha, squash_sha)`.
    - If `CorruptSquashError` raised: return `ActionOutcome(success=False, error_message=str(e))`.
    - Return `ActionOutcome(success=True, error_message=None)`.

    `_verify_squash(client, owner, repo, pr, pre_squash_develop_sha, squash_sha)`:
    This function implements IO-05 (Pitfall 8 defense — April 2026 incident) AND ROADMAP SC#3 verbatim: "asserts `commit.parents[0]` matches the pre-merge tip plus tree-diff sanity."

    Implementation in two phases:

    PHASE A — Parent SHA assertion (parents[0]):
    - Retry up to 3 times (1s, 2s exponential backoff via `time.sleep`) on `RequestFailed` with status 404 (read replication lag per RESEARCH.md UK-4). On final 404, propagate `RequestFailed`.
    - After successful `repos.get_commit(owner, repo, squash_sha)` read: `commit = response.parsed_data`.
    - Assert `commit.parents` is non-empty and `commit.parents[0].sha == pre_squash_develop_sha`.
    - If assertion fails: raise `CorruptSquashError(f"PR #{pr.number} squash {squash_sha!r}: expected parent {pre_squash_develop_sha!r}, got {commit.parents[0].sha!r}")`.
