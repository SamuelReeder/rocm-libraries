<objective>
Build `executor.py` — the I/O dispatcher that receives inert `Action` data from `decide_cycle` and produces GitHub mutations. The executor implements the RFC §4.9 activation state machine (merge-develop into PR branch → handle 204/201/409 → pre-stamp race check → stamp activation status → flip labels), the Pitfall 8 post-squash readback (`_verify_squash` asserting `commit.parents[0].sha == pre_squash_tip`), the eject handler (overwrite status to failure + cleanup labels), and the lazy comment-ID discovery for `UpdateComment`. Per-handler idempotency tests cover every second-call scenario from RESEARCH.md UK-3. Addresses IO-03, IO-04, IO-05.

Purpose: Connects Phase 1's pure decision output to real GitHub mutations. Idempotency is a load-bearing property for the 3-min cron processor (a cycle that crashes mid-execution must be safe to retry). Post-squash verification (Pitfall 8) defends against the April-2026 GitHub silent corruption incident.

Output: `executor.py` with `dispatch()` function and five handler functions; `test_executor.py` with ≥20 tests covering all dispatch rows + idempotency scenarios + post-squash verification.
</objective>

    Implementation rules for `executor.py`:
    - Module docstring: "rocm_mq.executor — Action dispatcher; executes GitHub mutations for each Action from decide_cycle. NOT in PURE_LAYER_MODULES; intentionally imports githubkit via GitHubClient."
    - `from __future__ import annotations` first.
    - Import `assert_never` from `typing` (stdlib 3.11+) — same pattern as `decision.py` (01-02-SUMMARY.md: "from typing import assert_never").
    - Import `RequestFailed` from `githubkit.exception` for error handling.
    - Import `CorruptSquashError` from `rocm_mq.gh`.
    - Import `Action, ActionOutcome, Activate, Squash, Eject, UpdateComment, Defer` from `rocm_mq.state`.
    - `_STATUS_MARKER = "<!-- rocm-mq-status -->"` — matches the constant in `comment.py` exactly (01-03-SUMMARY.md: "_STATUS_MARKER literal is load-bearing for comment upsert").

    `dispatch(action: Action, client: GitHubClient, owner: str, repo: str) -> ActionOutcome`:
    ```
    match action:
        case Activate(pr=pr):
            return _handle_activate(pr, client, owner, repo)
        case Squash(pr=pr):
            return _handle_squash(pr, client, owner, repo)
        case Eject(pr=pr, reason=reason):
            return _handle_eject(pr, reason, client, owner, repo)
        case UpdateComment(pr=pr, new_body=body):
            return _handle_update_comment(pr, body, client, owner, repo)
        case Defer(pr=pr, reason=reason):
            return ActionOutcome(action=action, success=True, error_message=None)
        case _:
            assert_never(action)
    ```

    `_handle_activate(pr: PRState, client, owner, repo) -> ActionOutcome`:
    - Calls `client.rest.repos.merge(owner, repo, base=pr_branch_name, head="develop")`.
    - If 201: `new_sha = response.parsed_data.sha`.
    - If 204: re-reads PR head SHA via `pulls.get(...).parsed_data.head.sha` → `new_sha`.
    - If `RequestFailed` with status 409: return `ActionOutcome(success=False, error_message="merge conflict with develop")`.
    - Pre-stamp race check: re-read `pulls.get(...).parsed_data.head.sha`; if != `new_sha`, return `ActionOutcome(success=False, error_message="pre-stamp race: PR head advanced since develop merge")`.
    - Stamp: `client.rest.repos.create_commit_status(owner, repo, new_sha, state="success", context=config.activation_status_context)`.
    - Label flip: `client.rest.issues.add_labels(owner, repo, pr.number, data=[config.active_label])`. Then `_safe_remove_label(client, owner, repo, pr.number, config.queued_label)`.
    - Return `ActionOutcome(action=action, success=True, error_message=None)`.
    - Note: `pr_branch_name` must come from somewhere — `PRState` does not have a branch name field. Add it OR use the PR number with a default `refs/pull/{number}/head` pattern. Preferred: add `branch: str` field to `PRState` in state.py (frozen dataclass extension — backwards compatible; all existing code that constructs `PRState` must add `branch=""` or a real value). Alternatively, the executor can accept `branch` as a separate parameter. Choose and document in the summary.

    `_safe_remove_label(client, owner, repo, pr_number, label)`:
    - Calls `client.rest.issues.remove_label(owner, repo, pr_number, label)`.
    - Catches `RequestFailed` with status 404 → pass (already absent = no-op per RESEARCH.md UK-3).
    - All other exceptions propagate.

    `_handle_squash(pr: PRState, client, owner, repo) -> ActionOutcome`:
    - Records `pre_squash_develop_sha` by reading current develop HEAD.
    - Calls `client.rest.pulls.merge(owner, repo, pr.number, merge_method="squash")`.
    - If `RequestFailed` with status 405: return `ActionOutcome(success=True, error_message="already merged — no-op")`.
    - On success: `squash_sha = response.parsed_data.sha`.
    - Calls `_verify_squash(client, owner, repo, pr, pre_squash_develop_sha, squash_sha)`.
    - If `CorruptSquashError` raised: return `ActionOutcome(success=False, error_message=str(e))`.
    - Return `ActionOutcome(success=True, error_message=None)`.

    `_verify_squash(client, owner, repo, pr, pre_squash_develop_sha, squash_sha)`:
    - Retry up to 3 times (1s, 2s backoff) on `RequestFailed` with status 404 (read replication lag).
    - After successful read: `commit = response.parsed_data`.
    - Assert `commit.parents` is non-empty and `commit.parents[0].sha == pre_squash_develop_sha`.
    - If assertion fails: raise `CorruptSquashError(f"PR #{pr.number} squash {squash_sha!r}: expected parent {pre_squash_develop_sha!r}, got ...")`.
    - This implements IO-05 (Pitfall 8 defense — April 2026 incident).

    `_handle_eject(pr: PRState, reason: str, client, owner, repo) -> ActionOutcome`:
    - Overwrites activation status: `create_commit_status(owner, repo, pr.head_sha, state="failure", context=config.activation_status_context)`.
    - Cleans up all `mq:*` labels via `_safe_remove_label` for each label in `pr.labels` that starts with config.label_prefix.
    - Returns `ActionOutcome(success=True)`.

    `_handle_update_comment(pr: PRState, body: str, client, owner, repo) -> ActionOutcome`:
    - Calls `_find_status_comment_id(client, owner, repo, pr.number)`.
    - If comment_id found: calls `issues.update_comment(owner, repo, comment_id, body=body)`.
    - If not found: calls `issues.create_comment(owner, repo, pr.number, body=body)`.
    - Returns `ActionOutcome(success=True)`.

    `_find_status_comment_id(client, owner, repo, pr_number) -> int | None`:
    - Calls `issues.list_comments(owner, repo, pr_number)`.
    - Iterates pages; finds first comment whose body contains `_STATUS_MARKER`.
    - Returns `comment.id` or `None`.

    Note on `config` availability in executor: `dispatch()` currently takes `(action, client, owner, repo)`. The executor also needs `config` for label names and activation_status_context. Options: (a) add `config: MergeQueueConfig` parameter to `dispatch()`, (b) use hardcoded defaults matching RFC §4.3. Preferred: add `config: MergeQueueConfig` to `dispatch()` signature — executor should not hardcode label names.
